[NATURAL LANGUAGE]
The attack begins with an initial exploit targeting a publicly facing web application (T1190) within the financial institution’s cloud environment. This application, a customer portal hosted on AWS Elastic Beanstalk, suffers from a known, but unpatched, SQL injection vulnerability. A malicious actor gains access to sensitive user credentials stored in clear text within the application’s database. These credentials belong to a legitimate employee with broad permissions within the organization’s Azure Active Directory (AAD).

Leveraging these valid accounts (T1078), the attacker performs reconnaissance to identify other services accessible via the compromised credentials. They discover that the employee has access to a cloud storage bucket containing customer financial data. The attacker then utilizes the compromised account to enumerate additional cloud credentials stored within the instance metadata service (IMDS) of an EC2 instance used for batch processing data (T1098.001). These credentials provide access to a more privileged role, granting read and write access to multiple sensitive resources.

With increased privileges, the attacker focuses on data exfiltration (T1567.002). They identify a database instance storing highly sensitive customer financial records and begin downloading the data in compressed format. To further obfuscate their activities and increase the impact, the attacker encrypts the exfiltrated data using a publicly available encryption tool (T1486). The encrypted data is then uploaded to a cloud storage bucket controlled by the attacker.

Simultaneously, the attacker initiates a lateral movement campaign, attempting to compromise other systems within the internal network. They leverage the compromised AAD account to attempt credential stuffing against other services, such as VPN concentrators and domain controllers. While these attempts are unsuccessful, they successfully gain access to a less secure development environment, where they deploy a backdoor for future access. This backdoor allows them to maintain persistence and continue reconnaissance efforts.

The attack concludes with the successful exfiltration of highly sensitive financial data, potentially leading to significant financial loss and reputational damage for the organization. The attacker’s ability to exploit a known vulnerability, leverage valid accounts, and utilize cloud metadata services highlights the importance of robust security controls and regular patching in cloud environments. The use of encryption and a backdoor for future access demonstrates the attacker’s sophistication and intent to cause long-term harm.

[NATURAL LANGUAGE]
The attack begins with a successful exploit of a publicly facing web application (T1190) within the financial institution’s cloud environment, specifically a customer-facing portal hosted on an Amazon Web Services (AWS) Elastic Beanstalk environment. This application, while not directly sensitive, contains a vulnerability allowing initial code execution. Once inside, the attacker leverages valid accounts (T1078) – specifically, a service account with limited permissions but access to a cloud storage bucket containing configuration files for internal systems – to establish a foothold. This service account was initially created for automated backups but lacks multi-factor authentication (MFA) and has overly permissive IAM roles assigned. The attacker then identifies a misconfiguration in the IAM role associated with this service account: it has been granted access to read metadata tags on other resources within the same AWS account.

Lateral movement occurs by exploiting the ability to read metadata tags on EC2 instances. The attacker discovers a tag containing the IAM role ARN of a privileged administrator role. This role, designed for system maintenance, has unrestricted access to all resources within the organization’s AWS account, including sensitive data stored in S3 buckets and databases running on RDS. The attacker uses the compromised service account to assume the role of the privileged administrator, bypassing traditional security controls. This escalation of privileges allows the attacker to gain full control over the cloud infrastructure.

Once in the privileged role, the attacker begins data exfiltration (T1567.002). They identify a critical S3 bucket containing customer financial records and encrypt the data using a publicly available encryption tool (T1486). The encrypted data is then uploaded to a malicious cloud storage account controlled by the attacker. To cover their tracks and prevent detection, the attacker modifies the IAM policy of the administrator role to restrict audit logging and alerting. The attack concludes with the successful exfiltration of sensitive customer data, potentially leading to significant financial loss and reputational damage for the financial institution.

[NATURAL LANGUAGE]

In the DUMMY-MVP-001 campaign, the adversary initially targeted an internet-facing application of a financial institution (K: Financial and insurance activities). Leveraging publicly known vulnerabilities (T1190), they successfully exploited the application to gain initial access.

Once inside, the adversary began a stealthy credential harvesting operation (T1078) by utilizing built-in tools such as PowerShell scripts and command-line utilities to gather administrative credentials from memory dumps and configuration files.

To maintain persistence within the environment, the adversary established a backdoor using a living-off-the-land binary (T1086). As time passed, the adversary gained access to additional cloud credentials (T1098.001) by exploiting misconfigurations in cloud storage and metadata services. They then utilized these credentials to move laterally across the cloud infrastructure, further expanding their foothold within the environment.

During this dwell phase, the adversary took steps to cover their tracks by tampering with log files and system audit trails (T1114). They deleted sensitive logs and modified others, making it difficult for security personnel to detect their presence.

Finally, to maximize the impact of their intrusion, the adversary encrypted sensitive data (T1486) stored in cloud services using a custom ransomware variant. The encryption process was designed to be slow and unobtrusive, allowing the adversary to exfiltrate the encrypted data to cloud storage (T1567.002) over a prolonged period.

[NATURAL LANGUAGE]
The attack begins with a successful exploit of a publicly facing web application (T1190) within the financial institution’s customer portal. This application, while not critical infrastructure, serves as a foothold into the network. The initial exploit leverages a known vulnerability in a third-party library used by the application. This task executes a simple script that downloads and installs a custom backdoor, disguised as a legitimate system utility. This backdoor provides remote access and command execution capabilities.

Lateral movement occurs by leveraging valid accounts (T1078) obtained through credential stuffing – utilizing common password patterns against the organization’s Active Directory. These accounts grant limited access to internal systems, including a file server hosting sensitive customer data. The attacker then utilizes living-off-the-land binaries (T1059.001) to perform reconnaissance and identify systems with more privileged access. Specifically, they target systems with access to cloud metadata services, identifying instances with exposed IAM roles allowing excessive permissions.

A key step involves harvesting additional cloud credentials (T1098.001) from these systems. This is achieved by dumping the contents of the AWS EC2 instance metadata service, revealing temporary credentials with broad permissions. These credentials are then used to assume roles with access to sensitive data stores, such as an S3 bucket containing customer financial records. The attacker carefully avoids triggering alert thresholds by limiting their activity and blending in with normal network traffic.

To establish long-term persistence and ensure continued access, the attacker creates a new IAM user with overly permissive access (T1027.003 - Domain Account) and assigns it to a role with access to critical data. This user is then used to exfiltrate data (T1567.002) to a cloud storage service owned by the attackers. To cover their tracks, the attacker attempts to tamper with log files and system audit trails, deleting or altering entries related to their activity.

The final impact is a significant data breach, resulting in the theft of thousands of customers’ financial information. The exfiltrated data is encrypted using a custom encryption algorithm (T1486) before being transferred to the attacker’s infrastructure. The attackers maintain persistent access to the environment, positioning themselves for future operations or ransom demands.

[NATURAL LANGUAGE]
The attack begins with a successful exploit of a publicly facing web application (T1190) within the financial institution’s customer portal. This application, while not critical to core banking operations, contains sensitive customer data including financial account numbers, addresses, and email addresses. The initial foothold grants access to a valid account (T1078) with limited privileges, specifically designed for customer service representatives. This account is not flagged for elevated monitoring due to its perceived low risk. Once inside, the attacker leverages the compromised account to harvest additional cloud credentials stored in plaintext within a misconfigured database (T1098.001). Lateral movement occurs through exploiting overly permissive IAM roles assigned to the compromised VM. The attacker gains access to a central metadata service, allowing them to enumerate other cloud resources and identify the storage bucket containing customer data. A key misconfiguration here is the lack of multi-factor authentication (MFA) on the metadata service, making it easier to compromise. With access to the storage bucket, the attacker begins staging data for exfiltration (T1567.002). They compress and encrypt the data using a custom ransomware variant (T1486), mirroring the tactics of well-known threat actors like Ryuk and Conti.

The ransomware is then deployed across the remaining VMs, encrypting critical data and systems. The financial institution’s backup strategy, relying on tape storage, proves ineffective against this attack. The attacker simultaneously initiates exfiltration of the encrypted data to a cloud storage account controlled by the attackers. The data is compartmentalized and encrypted, making it difficult for security teams to decipher the contents without the attacker’s decryption key. The attacker demands a significant ransom in exchange for the decryption key and the return of the stolen data.

The business impact is severe. The financial institution faces regulatory fines for data protection violations, reputational damage, and potential legal liabilities for exposing customer data. The ransom demand further strains the organization’s financial resources. The delay in restoring operations leads to lost revenue, customer dissatisfaction, and potential long-term financial instability. The exfiltrated data could be used for identity theft, financial fraud, or extortion. The attackers’ ability to move laterally and escalate privileges underscores the importance of robust IAM policies and secure configuration management practices.
