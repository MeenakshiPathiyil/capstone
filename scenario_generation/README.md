## 1 — Dataset Pipeline

Install dependencies:
```bash
pip install -r dataset_pipeline/requirements.txt
```

Download ATT&CK STIX bundle (~50MB, gitignored):
```bash
curl -L -o dataset/raw/enterprise-attack-18.1.json \
  "https://raw.githubusercontent.com/mitre-attack/attack-stix-data/master/enterprise-attack/enterprise-attack-18.1.json"
```

Parse STIX into structured inputs:
```bash
python dataset_pipeline/parse_stix.py \
  --stix dataset/raw/enterprise-attack-18.1.json \
  --out  dataset/inputs/
```

Expected output: 209 entries across campaigns and threat actor groups, saved to `dataset/inputs/training_inputs.jsonl`.

Generate tri-modal training records via Claude API:
```bash
export ANTHROPIC_API_KEY=your_key_here
python dataset_pipeline/generate_outputs.py \
  --inputs dataset/inputs/training_inputs.jsonl \
  --out    dataset/training_data.jsonl \
  --limit  80 \
  --model  claude-haiku-4-5-20251001
```

Expected output: 81 records in `dataset/training_data.jsonl` in `instruction / input / output` format.

## 2 — Fine-Tuning (QLoRA)

### What QLoRA does
- **Q (Quantization):** loads Mistral-7B in 4-bit precision (~4GB VRAM instead of ~28GB)
- **LoRA:** attaches small adapter matrices to attention layers — only these are trained, not the full 7B weights
- **Result:** 13.6M trainable parameters out of 7.26B total (0.19%) — runnable on a free Colab T4 GPU

### Completed training run
- Base model: `mistralai/Mistral-7B-Instruct-v0.3`
- Dataset: 81 records (64 train / 17 val, 80/20 split)
- Epochs: 3 — Steps: 48
- LoRA rank: 16, alpha: 32, target modules: `q_proj`, `v_proj`, `k_proj`, `o_proj`
- GPU: Tesla T4 (Google Colab)
- Adapter saved to: `fine_tuning/output/adapter_model.safetensors` (gitignored, ~21MB compressed)

### Install dependencies
```bash
pip install -r fine_tuning/requirements_finetune.txt
```

### Run locally
```bash
python fine_tuning/fine_tune.py \
  --data dataset/training_data.jsonl \
  --out  fine_tuning/output/
```

### Run in Colab

- Open `fine_tuning/colab_finetune_setup.ipynb`
- Run the install cell first, then restart the runtime
- Run the verification cell to confirm all packages imported cleanly
- Upload `training_data.jsonl` and both `.py` files when prompted
- Run the inline training cell (not the subprocess cell)
- Download `finetuned_adapters.zip` from the final cell before ending the session — Colab storage is ephemeral

### Known Colab issue and fix
The original `!python` subprocess approach caused a BFloat16 mixed precision error on T4 (`_amp_foreach_non_finite_check_and_unscale_cuda not implemented for BFloat16`). Fixed by running training inline in the notebook with `os.environ["ACCELERATE_MIXED_PRECISION"] = "no"` set before any imports, and `fp16=False, bf16=False` in `SFTConfig`.

## 3 — Evaluation

Create held-out test inputs (excludes training examples):
```bash
python evaluation/make_test_inputs.py \
  --inputs      dataset/inputs/training_inputs.jsonl \
  --out         evaluation/test_inputs.jsonl \
  --train_count 80 \
  --sample_size 10
```

Evaluate base vs fine-tuned model:
```bash
export ANTHROPIC_API_KEY=your_key_here
python evaluation/evaluate.py \
  --base_model   mistralai/Mistral-7B-Instruct-v0.3 \
  --adapter_path fine_tuning/output \
  --test_inputs  evaluation/test_inputs.jsonl \
  --out          evaluation/evaluation_results.json
```

Metrics scored 1–10 by a judge LLM panel (matching the base paper):
- **Level of Detail** — how thoroughly the scenario covers the attack
- **Technical Accuracy** — correctness of techniques, CVEs, and attack logic
- **Realism** — plausibility of the attack narrative
- **Creativity** — originality and non-obviousness of the attack path

## Output Format

Each training example contains three fields:

- `instruction` — task description with attack level and industry context
- `input` — structured attack details (source, techniques, surfaces, vectors, scenario seed)
- `output` — tri-modal scenario with three sections:
```
[NATURAL LANGUAGE]
Readable attack narrative for non-technical stakeholders.

[MATHEMATICAL EXPRESSION]
G = (N, S, V, P, FS) where:
N = {n1: ..., n2: ...}
S = {s1: ..., s2: ...}
V = {v1: ..., v2: ...}
P = {p1: n1→n2 via v1, ...}
FS = Full attack achieving [objective]

[ATTACK GRAPH]
Stage 1 — [Name]: [Node] | Technique: [ATT&CK ID] | Pre: [...] | Post: [...]
Stage 2 — ...
```

## Known Notes

- Attack-level distribution skews toward `medium`/`high` — ATT&CK descriptions rarely use "novice" or "script kiddie" language, so the `low` heuristic rarely fires. Planned fix: manual overrides for a subset of entries.
- Colab runtime is ephemeral — always download the adapter zip before ending the session.
- The `adapter_model.safetensors` file (~21MB compressed, ~26MB uncompressed) is gitignored. Store it separately (Google Drive, HuggingFace Hub, or local disk) and reference the path in `evaluate.py`.
- Dataset files (`training_data.jsonl`, `inputs/`, `raw/`) are gitignored — run the pipeline scripts to reproduce them.
